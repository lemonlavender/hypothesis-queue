# Hypothesis Queue · 假设验证队列

[English](README.md) · MIT · iPolloWork 插件

把 AI 辅助研究中的想法整理为具体的验证队列。为每个假设明确可测量预测、否定条件、验证方法、负责人和预计工时，再判断当前时间预算内能安排哪些工作。

面向 [iPolloWork](https://github.com/Devin-AXIS/iPolloWork) 使用，提供可直接导入的 `.ipollowork-plugin`、中英文工作区面板和两个模型工具。

**1.0.0 已在 iPolloWork 0.50.12 / macOS arm64 / OpenCode / GPT-5.5 验证。** 文件导入、界面编辑、真实模型工具、升级、窗口重载和卸载重装均通过，实际结果见[验收记录](docs/desktop-acceptance.md)。

## 适合谁使用

适合研究人员、AI 评测团队和产品团队：候选解释很多，验证时间有限。可用于每周验证计划、整理研究助手提出的想法，或向同事交接待验证假设。

插件区分“还需要完善设计的想法”和“信息完整但本周预算放不下的验证工作”。它整理已提供的信息，不判断研究是否科学可靠。

## 功能与流程

- 手动粘贴 JSON，或由模型工具导入最多 100 个假设。
- 标明缺失的来源、预测、否定条件、方法、负责人和预计工时。
- 编辑假设、调整共享工时预算、暂存任务并重新排入。
- 按固定顺序排队：优先级 1 优先，其次工时更少，最后按 ID。
- 记录支持、不支持或尚无定论的观测结果，并要求填写记录。
- 导出可重新导入的 JSON 和中英双语 Markdown；切换中英文界面。

只有信息完整、未暂存且尚未记录结果的假设参与排队。插件依次检查排序后的项目，放得下就安排，放不下就跳过并继续。规则公开透明，但不保证全局最优，也不是统计检验。

## 在 iPolloWork 中安装和打开

前置条件：iPollo 桌面软件和已选中的本地项目。手动操作无需模型、额外账号、API Key 或安装依赖；模型工具还需要宿主已有的可用模型与引擎。

1. 从 [Releases](https://github.com/lemonlavender/hypothesis-queue/releases) 下载 `hypothesis-queue-<版本>.ipollowork-plugin`，或按下文构建。
2. 打开 **扩展 → 插件 → 添加 → 文件**。
3. 选择安装包，确认名称 **Hypothesis Queue / 假设验证队列**、发布者 **lemonlavender**、版本及一个 UI 资源。
4. 安装、启用资源，按宿主提示重新加载。
5. 打开项目中的任务，点击 **打开右侧面板 → + / 添加侧面板入口 → Hypothesis Queue**。
6. 点击 **载入示例**，或粘贴 `examples/research-queue.json` 到 **Queue JSON / 队列 JSON**，点击 **替换队列**。

普通安装请使用安装包；任意 GitHub 链接和源码 ZIP 不是通用安装入口。

## 完整示例

附带的文档研究完全是模拟数据，四个假设共享 **4 小时**预算：

| ID | 优先级 | 工时 | 初始状态 |
|---|---:|---:|---|
| H1：带来源引用的 AI 草稿 | 1 | 2 小时 | 已排入 |
| H2：审阅检查清单 | 1 | 3 小时 | 预算不足 |
| H3：显示不确定性 | 2 | 1 小时 | 缺少否定条件、方法和负责人 |
| H4：术语表 | 2 | 1.5 小时 | 已排入 |

顺序为 **H1 → H4**，共 **3.5 小时**，剩余 **0.5 小时**。H1 排入后 H2 放不下，H4 可以放入。

1. 把可用工时改成 **5**，点击 **应用预算**，顺序变成 **H1 → H2**。
2. 选择 H3，填写真实的否定条件、方法和负责人，点击 **保存假设**。不要为了排入队列而编造证据。
3. 选择 H1 练习结果记录：保留 **尚无定论**，填写“模拟案例：只审阅了 20 项中的 8 项，完整结果尚不可用”，点击 **保存结果**。
4. H1 变为 **已记录结果**，不再占用待执行工作的预算。这不代表插件执行或独立验证了实验。
5. **重新进入验证** 会清除结果。修改假设、来源、预测、否定条件或方法，也会清除旧结果；修改负责人、工时或优先级不会。
6. 导出 JSON 或 Markdown，把可见内容复制到项目文件；后续导入 JSON 即可恢复。

`examples/expected-plan.json` 和 `expected-handoff.md` 是纯排队模块根据原始示例生成的预期输出，不是桌面验收证据。

真实安装插件的输出另存为 [desktop-plan.json](examples/desktop-plan.json)、[desktop-queue.json](examples/desktop-queue.json) 和 [desktop-plan.md](examples/desktop-plan.md)，由实际模型工具流程保存，并与示例核对；没有执行实验。

## 配合模型使用

先打开插件面板，把示例 JSON 放进本地项目，再发出请求：

> 使用 Hypothesis Queue 的 load_queue 工具导入 research-queue.json，然后调用 get_queue。将其中的 queue 保存为 hypothesis-queue.json，将 Markdown 文本保存为 hypothesis-plan.md。不要执行实验，不要编造观测结果。

宿主可能给工具名称加前缀。`load_queue` 接受 `{ "queue": ... }`，替换可见队列；`get_queue` 返回队列、选中 ID、各项状态、数量、已用与剩余工时以及 Markdown。输入被视为数据，而不是指令。工具不执行实验、不浏览外网、不在面板外安排任务，也不自动完成科学审查。

界面修改后需再次调用 `get_queue`，旧回复不会包含后续编辑。模型生成的文件仍需人工检查。

## 数据保存与限制

完整字段见[数据格式](docs/data-format.md)。预算以 0.25 小时为步长；未知工时填 `null`。优先级由使用者提供，不根据 AI 的自信程度推断。

JSON 导出的是可直接恢复的**队列对象**。较大的工具计划回执把它放在 `queue` 字段；不要导入整个回执。Markdown 用于阅读，不是导入格式。

面板只在内存中保存当前工作。**关闭、重新加载、升级或卸载前请先导出。** 项目导出文件与插件安装文件相互独立。重新打开空面板后，导入保存的 JSON 即可恢复。

插件本身不向外部服务发请求。模型工具会通过 iPollo 已有配置把队列提供给当前模型服务商，请只传入您有权提供的数据。

“信息完整”不能证明方法有效、来源真实或否定条件充分。共享工时池不处理任务依赖、个人日历、设备档期或日历截止时间。记录结果不代表统计显著性、因果关系或可重复性成立。

其他系统、引擎、完整进程重启和真实科研流程均未验证。本项目为独立工具，不是 Google 或 iPolloWork 官方认证或服务集成。

## 构建和继续开发

需要 **Node.js 22+**，以及 PATH 中的 `zip`、`unzip`，无需 npm 依赖。

```sh
npm test
npm run package
```

`src/queue.mjs` 实现校验、排队和导出；`src/index.template.html` 提供双语界面与宿主通信；`scripts/build.mjs` 生成自包含 `ui/index.html`；`package.mjs` 从干净 staging 打包，只包含 HTML 和根清单，固定文件顺序、权限及时间戳。

源码 ZIP 与安装包分开。把 Release 文件和 `SHA256SUMS` 下载到同一目录后运行：

```sh
shasum -a 256 -c SHA256SUMS
```

校验和只验证文件身份，不替代运行验收。已发布版本的安装包字节不可修改；改变运行内容时递增语义版本，并保持 ID、发布者及 update ID 稳定。

## 常见问题

**为什么某个假设没排上？** 行内会说明待补信息、已暂存、已记录结果或预算不足。优先级 1 最高。

**为什么跳过高优先级长任务？** 先排入的任务占用预算后，它放不下。算法继续尝试较小任务，不求解最优组合。

**无效导入会丢失工作吗？** 不会。JSON、未知字段、重复 ID 和非法数值先校验后替换，错误保留当前队列。

**工具不可见怎么办？** 确认当前任务已打开并启用面板，明确请求工具；仍不可用时用手动 JSON 流程，并记录宿主与引擎限制。

**不用模型能导出吗？** 可以：导出、**Select all / 全选**、复制，再用自己的编辑器保存。面板不声称有自动文件系统访问能力。
