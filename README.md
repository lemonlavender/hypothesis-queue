# Hypothesis Queue

[简体中文](README.zh-CN.md) · MIT · iPolloWork plugin

Turn AI-assisted research ideas into a concrete validation queue. Give each hypothesis a measurable prediction, a falsifying condition, a method, an owner and an effort estimate; then see what fits the time you have.

Designed for [iPolloWork](https://github.com/Devin-AXIS/iPolloWork), with a ready-to-import `.ipollowork-plugin`, a bilingual workspace panel and two model tools.

**Version 1.0.0 verified on iPolloWork 0.50.12 / macOS arm64 / OpenCode / GPT-5.5.** File import, UI editing, actual model tools, upgrade, window reload and reinstall passed. See [acceptance](docs/desktop-acceptance.md) for the observed results.

## Who it helps

Researchers, AI evaluation teams and product teams often have more candidate explanations than time to test them. Use this panel to prepare a weekly validation plan, triage ideas from a research assistant, or hand an experiment backlog to a colleague.

It distinguishes an idea that needs more design from a complete test that does not fit this week's capacity. It organizes supplied information; it does not judge scientific quality.

## Capabilities and workflow

- Import up to 100 hypotheses from JSON, manually or through a model tool.
- Find missing sources, predictions, falsifiers, methods, owners and effort estimates.
- Edit hypotheses, change the shared hours budget, park work and reopen it.
- Build a deterministic queue: priority 1 first, then smaller effort, then ID.
- Record supporting, contradicting or inconclusive observations with mandatory notes.
- Export re-importable JSON and a bilingual Markdown handoff; switch between English and Chinese UI.

Only complete, unparked hypotheses without a recorded outcome compete for capacity. The planner walks the sorted list, selects work that fits and skips oversized items. This is a transparent heuristic, not a globally optimal schedule or statistical test.

## Install and open in iPolloWork

Prerequisites: the iPollo desktop app and a selected local project. Manual use needs no model, extra account, API key or package installation. Model tools additionally need your existing working model/engine configuration.

1. Obtain `hypothesis-queue-<version>.ipollowork-plugin` from [Releases](https://github.com/lemonlavender/hypothesis-queue/releases), or build it below.
2. Open **Extensions → Plugins → Add → File** (`扩展 → 插件 → 添加 → 文件`).
3. Select the installation archive. Check **Hypothesis Queue**, publisher **lemonlavender**, the version, and one UI resource.
4. Install, enable the resource and reload if prompted.
5. Open a project task. Choose **Open right panel**, then **+ / Add side-panel entry**, then **Hypothesis Queue**.
6. Click **Load example**, or paste `examples/research-queue.json` into **Queue JSON** and click **Replace queue**.

Use the installation archive. A generic GitHub URL and the source ZIP are not the normal installation path.

## Complete example

The included documentation study is entirely synthetic. Four hypotheses share **4 hours**:

| ID | Priority | Effort | Initial disposition |
|---|---:|---:|---|
| H1 — source-linked drafts | 1 | 2 h | Selected |
| H2 — review checklist | 1 | 3 h | Over budget |
| H3 — uncertainty display | 2 | 1 h | Missing falsifier, method and owner |
| H4 — terminology glossary | 2 | 1.5 h | Selected |

The selected order is **H1 → H4**, using **3.5 hours**, with **0.5 hours** remaining. H2 cannot fit after H1; H4 can.

1. Change capacity to **5**, then **Apply budget**. The plan becomes **H1 → H2**.
2. Select H3, add your own falsifier, method and owner, then **Save hypothesis**. Do not invent evidence to make an item ready.
3. Select H1. For a result-workflow exercise, keep **Inconclusive** and enter “Synthetic example: only 8 of 20 items reviewed; full result unavailable.” Click **Save outcome**.
4. H1 moves to **Outcome recorded** and no longer consumes the pending-work budget. The plugin has not run or independently verified an experiment.
5. **Reopen hypothesis** clears its result. Editing the claim, source, prediction, falsifier or method also clears an old result; changing owner, effort or priority does not.
6. Export JSON or Markdown. Copy the visible output into a project file; re-import JSON to resume.

`examples/expected-plan.json` and `expected-handoff.md` are generated by the pure planning module from the original sample. They are examples, not desktop test evidence.

The actual installed-plugin output is included separately as [desktop-plan.json](examples/desktop-plan.json), [desktop-queue.json](examples/desktop-queue.json) and [desktop-plan.md](examples/desktop-plan.md). These were saved through the real model tool workflow and checked against the sample; no experiment was executed.

## Model tools

Keep the panel open. Copy the sample JSON into your local project, then ask:

> Use Hypothesis Queue's load_queue tool with research-queue.json, then call get_queue. Save its queue field as hypothesis-queue.json and its Markdown text as hypothesis-plan.md. Do not run experiments or invent observations.

The host may prefix tool names. `load_queue` accepts `{ "queue": ... }` and replaces the visible queue. `get_queue` returns the queue, selected IDs, dispositions, counts, used/remaining hours and Markdown. Input is data, not instructions. Neither tool performs experiments, browsing, external scheduling or autonomous scientific review.

After UI changes, call `get_queue` again; earlier responses do not include later edits. Review model-generated files before using them.

## Data, persistence and limits

See [data format](docs/data-format.md). Budgets use quarter-hour steps; unknown effort is `null`. Priorities are supplied by the user, not inferred from AI confidence.

JSON export is the **queue itself**, ready to re-import. A tool planning receipt contains it as `queue`; do not import the full receipt. Markdown is for reading, not importing.

The panel keeps work in memory. **Export before closing, reloading, upgrading or uninstalling.** Exported project files are separate from installed plugin files. Reopen an empty panel and import your saved JSON to resume.

The plugin sends no external network requests. Model tools share the queue with your existing iPollo model provider under its normal configuration; include only data you may send there.

Readiness means field completeness, not valid methodology, authentic evidence or adequate falsification. The single hours pool does not model dependencies, staff calendars, equipment or deadlines. Supplied outcomes do not establish significance, causality or replication.

Other platforms, engines, full process restarts and live research workflows are unverified. Independent tool; no Google or iPolloWork certification or service integration.

## Build and contribute

Development requires **Node.js 22+**, `zip` and `unzip` on PATH. No npm dependencies.

```sh
npm test
npm run package
```

`src/queue.mjs` handles validation, ranking and export. `src/index.template.html` implements the bilingual UI and host bridge. `scripts/build.mjs` creates self-contained `ui/index.html`. `package.mjs` packages only the UI and root manifest from clean staging, with fixed ordering, permissions and timestamps.

Source ZIP and installation archive are separate. Download release files and `SHA256SUMS` together, then run:

```sh
shasum -a 256 -c SHA256SUMS
```

A hash checks identity, not runtime behavior. Published package bytes are immutable: increment semver for runtime changes, and preserve ID, publisher and update ID.

## FAQ

**Why is an item not selected?** Its row identifies incomplete fields, parked work, a recorded outcome or insufficient capacity. Priority 1 is highest.

**Why skip a long high-priority item?** Earlier selected work left insufficient capacity. The planner continues with smaller items; it does not solve optimal packing.

**Does invalid import erase work?** No. JSON, unknown fields, duplicate IDs and invalid numbers are checked before replacement; errors preserve the current queue.

**Tools are missing?** Keep the enabled panel open in the current task. Ask explicitly for the tools; otherwise use manual JSON and report the host/engine limitation.

**Can I export without a model?** Yes: export, **Select all**, copy and save with your own editor. The panel does not claim automatic filesystem access.
